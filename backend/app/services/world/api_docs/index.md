# 群视界 API 文档总览（index）

> **读者**：群视界机器人（世界默认 AI）与编写世界代码的开发者
> **版本**：v1.0 ｜ **日期**：2026-08-05
> **接口规范**：RESTful + JSON，认证统一 `Authorization: Bearer <JWT>`

本文档按**功能分区**组织。每个分区只在此给出**区名与区介绍**，详细 API 在分区文档中；**AI 用 `view_api_doc` 工具按需打开分区**，人类开发者直接阅读 `sections/` 目录。

---

## 分区索引（区名 + 区介绍）

| 区号 | 区名 | 区介绍（何时看） |
|------|------|------------------|
| 01 | 世界编号变量 | window 注入的 `WORLD_ID / GROUP_ID / USER_ID / WORLD_AI_ID` 等变量与打包原则。**写任何世界页面代码前必读**，杜绝硬编码编号 |
| 02 | 世界UI桥 WorldUI | 控制宿主外壳：侧边栏/悬浮图标的显隐。实现了自己的导航时用 `hideFloatingIcon` 避免两套 UI 重复 |
| 03 | 文件操作 | `file_list / file_write / file_read / file_edit / file_delete` 全部参数与返回、类型白名单、越界防护、读取截断规则。**建/改世界网页代码前必读** |
| 04 | 积木体系 | `list_world_blocks / view_world_block / apply_world_block` 用法、现有积木（平台侧边栏、群聊对话窗）与侧边栏约定 |
| 05 | 群聊 API | 读消息/发消息/成员列表/角色管理/踢人工具：参数、返回、身份与权限约定（默认作用于本世界绑定群） |
| 06 | 页面与资源 | 沉浸界面预览入口、静态资源路由 `/world/{id}/files/`、相对路径规则、资源类型 |
| 07 | 懒通知与世界时间 | 用户手动改代码的通知机制（对话时取通知）、世界时间流速与运行模式（懒加载/后台任务） |
| 08 | 错误与安全 | 错误体格式、状态码表、认证要求、写操作身份与防护约定 |

## 给 AI 的使用方式（重要）

1. 你的工具列表里有 **`view_api_doc`**：传入区号（`01`~`08`）即可查看该区的完整详细 API。
2. **先看区介绍再开区**：上表已给出各区介绍——判断你要做的事落在哪个区，只打开需要的区，不要一次全读。
3. 常见对应关系：
   - 建网页/改代码 → **03 文件操作**（必要时 06 页面与资源）
   - 套用现成 UI 组件 → **04 积木体系**
   - 在群里发言/管群 → **05 群聊 API**
   - 需要知道当前用户/群编号 → **01 世界编号变量**
   - 遇到报错 → **08 错误与安全**

## 给开发者的阅读方式

- 分区详细文档：`sections/01-*.md` … `sections/08-*.md`（与 AI 通过工具读到的是同一份）
- 运行时目录：`data/world_api_docs/`（后端 `view_api_doc` 工具读取的位置，改文档即时生效，无需重启）

---

## 快速上手（给 agent 的 6 步）

1. 了解自己的身份与注入变量 → 打开 **01 世界编号变量**
2. 建立世界主页 → 打开 **03 文件操作**，写 `index.html`（+ css/js），`file_write` 自动建目录
3. 想套现成 UI → 打开 **04 积木体系**，`list_world_blocks` → `view_world_block` → `apply_world_block`
4. 用户从群聊进入世界后，你想在群里说话 → 打开 **05 群聊 API**，`send_group_message`（默认发到绑定群）
5. 用户手动改了代码 → 对话开始时读 **07 懒通知**，回复中体现"我看到你改了 xxx"
6. 随时改布局/加功能 → 继续写文件，保存即生效；报错查 **08 错误与安全**
